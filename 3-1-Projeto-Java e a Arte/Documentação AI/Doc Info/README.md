# Documentação Info — PetShop: Controle de Banho

## 1. Objetivo do projeto

Desenvolver um programa em Java para simular o funcionamento de um Pet Shop, utilizando orientação a objetos para representar um animal, controlar uma máquina de banho e permitir a interação por meio de um menu.

O projeto tem como objetivo praticar a criação de classes, atributos, métodos, encapsulamento, interação entre objetos e organização do código.

## 2. Estrutura do projeto

O projeto será desenvolvido com três classes:

**1. `Pet.java` — Representação do animal**

Responsável por representar o animal que utilizará a máquina de banho, armazenando suas informações e características.

**2. `PetMachine.java` — Controle da máquina de banho**

Responsável por controlar os recursos e as operações da máquina, incluindo:
- Verificar a disponibilidade da máquina.
- Colocar e retirar o animal.
- Controlar o banho.
- Controlar a limpeza da máquina.
- Gerenciar os recursos utilizados durante o funcionamento.

**3. `Main.java` — Execução do programa**

Responsável por iniciar o programa, apresentar o menu de opções e conectar as funcionalidades das classes `Pet` e `PetMachine`.

## 3. Requisitos e funcionamento

O programa deverá permitir a interação com a máquina de banho por meio de um menu.

As funcionalidades deverão respeitar as regras de funcionamento do exercício, incluindo o controle do animal, dos recursos disponíveis, do processo de banho e da limpeza da máquina.

As operações deverão ser realizadas por meio dos métodos definidos nas classes, mantendo suas respectivas responsabilidades.

## 4. Sequência de desenvolvimento

O projeto será desenvolvido em quatro etapas:

1. **Etapa 1 — `Pet.java`:** criação e validação da classe que representa o animal.
2. **Etapa 2 — `PetMachine.java`:** criação e validação da classe responsável pelo controle da máquina.
3. **Etapa 3 — `Main.java`:** criação do menu e conexão das funcionalidades.
4. **Etapa 4 — Integração:** apresentação dos três códigos completos, explicação de como trabalham juntos e registro das correções realizadas.

## 5. Critérios de conclusão

O projeto será considerado concluído quando:

- As três classes estiverem implementadas e revisadas.
- As funcionalidades estiverem conectadas corretamente.
- As regras de funcionamento forem respeitadas.
- Os testes confirmarem o funcionamento esperado.
- A integração dos três arquivos estiver concluída.

**Regra de desenvolvimento:** cada etapa será analisada e validada antes de avançarmos para a seguinte. A aprovação definitiva ocorrerá somente após a integração e os testes do projeto.
